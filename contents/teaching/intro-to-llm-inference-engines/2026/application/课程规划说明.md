# 《大模型推理系统与实践》课程规划说明

## 1. 课程定位

本课程面向计算机相关专业硕士研究生，定位为实践教学课程。课程围绕大模型推理系统的基本机制、工程实现和实验验证展开，以 vLLM-HUST / vLLM-Ascend-HUST 等开源推理系统为主要实践对象，训练学生完成问题复现、代码阅读、功能修复、性能评测、测试验证和 PR / patch 说明。

课程不以孤立 demo 为主要目标，而是要求学生按照开源项目流程完成一个有记录、可复现、可评审的实践任务。

## 2. 整体授课思路

课程按五个阶段组织：

1. 系统概念导入：建立请求生命周期、Prefill/Decode、连续批处理、KV Cache、状态管理和性能指标等基本概念。
2. 代码路径阅读：以 vLLM-HUST 为主要实践仓库，带领学生阅读 scheduler、worker、executor、attention backend、benchmark 脚本等关键路径。
3. 实验复现训练：通过 smoke test、小规模 benchmark 和 metadata 检查，让学生理解实验可复现要求。
4. 开源任务实践：学生分组认领 issue、benchmark 缺口、文档改进或小型功能修复，完成 patch、PR 或复现实验文档。
5. 结果汇报评审：围绕代码修改、测试结果、benchmark 数据、review 反馈和后续风险进行汇报。

## 4. 实践任务组织

- 任务来源：vLLM-HUST、vLLM-Ascend-HUST、vLLM-HUST benchmark、dev-hub 等仓库的 issue、PR 需求、benchmark 缺口和文档改进任务。
- 分组方式：2–3 人一组，每组认领一个可完成任务。
- 过程材料：issue 分析、环境记录、代码路径说明、实验脚本、测试结果、PR 链接或 patch、review 处理记录。
- 成果形式：PR、patch、benchmark 数据、复现实验文档或文档改进。
- 评价重点：流程规范、代码与实验可复现、问题解释清楚、遵守开源协作和工程规范。

## 5. 考核建议

- 课堂参与与阅读练习：20%
- 实验复现与过程记录：30%
- 课程项目 PR / patch / benchmark 数据：30%
- 期末汇报与总结报告：20%

## 6. 场地、设备与环境需求

- 授课场地：普通研究生机房或具备投影、网络和电源的研讨教室；项目工作坊和汇报环节建议使用可分组讨论的教室。
- 学生端设备：学生需自备笔记本电脑，能够运行 Linux、macOS 或 Windows + WSL2 环境，具备 Git、Python、Docker 或 Conda 等基本开发工具。
- 网络条件：需要可访问 GitHub、Python / npm / container 镜像源和课程代码仓库的校园网络；如网络访问受限，需提供校内镜像或预下载依赖包。
- 课程代码环境：使用 vLLM-HUST、vLLM-Ascend-HUST、vLLM-HUST benchmark、dev-hub 等仓库；课程开始前提供环境配置说明、基础 smoke test 和示例任务清单。
- 计算资源：基础代码阅读、单元测试、文档改进和小规模 benchmark 可在学生本机或通用 Linux 服务器完成；涉及 Ascend / NPU 后端、较大模型或多卡 benchmark 的任务需使用课题组或学院提供的共享服务器。
- 硬件需求：建议准备至少一台可远程访问的 Linux 服务器用于统一实验环境；如安排异构后端实践，需要具备 Ascend NPU 及对应 CANN、torch-npu、驱动和容器环境。多卡性能实验可作为选做或小组专项任务，按硬件排队情况安排。
- 账号与权限：需要为学生提供课程仓库访问说明、issue/PR 提交流程说明；服务器任务采用个人账号或小组账号，限定目录和配额，避免影响生产服务。
- 数据与模型：课程优先使用公开模型、公开 workload 或经过脱敏的 benchmark 数据；不得在课程项目中使用未经授权的数据、密钥或内部服务日志。
- 安全与管理：服务器使用需记录实验时间、模型、命令、资源占用和输出位置；涉及长时间 benchmark 的任务需提前预约，避免与其他科研任务冲突。
